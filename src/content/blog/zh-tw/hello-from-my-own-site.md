過去兩年我寫過不少網站，但它們幾乎都是為了黑客松而生：三天內生出來，demo 完就放著。有些跑在 Streamlit 上，有些用 Cloud Run 包了個容器丟上去。

然後它們就開始慢慢死掉。免費額度用完、依賴的套件版本漂移、當初隨手設的環境變數再也想不起來。半年後打開連結，看到的是一個冷啟動失敗的錯誤頁。

問題不在 Streamlit，也不在 Cloud Run——它們各自都是好工具。問題在於我用**跑一個應用程式**的方式，去承載**一份應該長期存在的紀錄**。

## 這次的做法

這個網站是靜態的。文章是 Markdown，存在 Git 裡；每次改動就重新建置成純 HTML 丟到 CDN 上。沒有伺服器要醒著，沒有容器會冷啟動，沒有東西會在我沒注意的時候過期。

換句話說：**它不會因為我三個月沒看它就壞掉。**

至於要發新文章，我從瀏覽器登入後台寫就好，背後仍然是提交一個 Markdown 檔案到 repo。內容永遠是我的，即使哪天整個平台收掉，我也只是換個地方重新建置。

## 這裡會有什麼

- 硬體相關的除錯筆記——特別是那種「模擬過了但上板不動」的
- 專案的技術決策紀錄，包含當初為什麼**沒有**選另一條路
- 黑客松的完整流水帳，包含沒得名的

第三項是刻意的。只放得獎紀錄的頁面看起來很漂亮，但那不是我實際在做的事情的樣子。
